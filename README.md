# تحويلاتي V9 — نسخة GitHub Pages

واجهة شخصية بسيطة لإدارة تحويلات الراتب. التطبيق يعمل داخل المتصفح ويحفظ البيانات محليًا على الجهاز نفسه، وليس في GitHub.

## رفع الموقع إلى GitHub Pages

1. فك ضغط ملف `tahweelati_github_pages.zip` على جهازك.
2. أنشئ Repository جديدًا في GitHub، أو افتح مستودعًا مخصصًا للموقع.
3. ارفع الملفات الموجودة **داخل** الحزمة (`index.html` و`README.md` و`.nojekyll`) إلى جذر المستودع على فرع `main`، **ولا ترفع ملف ZIP وحده**.
4. من إعدادات المستودع: **Settings → Pages → Build and deployment → Deploy from a branch**. اختر `main` و`/(root)` ثم احفظ.
5. افتح رابط GitHub Pages الذي يظهر بعد النشر: `https://USERNAME.github.io/REPOSITORY/`.
6. على الآيفون افتح الرابط في Safari واختر **مشاركة → إضافة إلى الشاشة الرئيسية**، إذا رغبت.

## الجديد في V9: وجهة تحويل المبلغ السالب

إذا ظهر صافي سالب لبند ضمن الراجحي أو STC أو برق، يظهر سطر صغير تحته يوضح المبلغ والحساب الرئيسي الذي ينبغي تحويل المبلغ إليه، بناءً على حساب استقبال التحويل الإجمالي في البنك.

مثال: Saving أساسه 500، وتسويته مع الحساب الجاري −1,200؛ يظهر Saving −700 ومعه **«حوّل 700 ريال إلى Investment»**. تظل تفاصيل التسوية الأصلية **−1,200 مع الجاري** محفوظة كما هي، ولا تتغير قيمة إجمالي الراجحي أو علامات الصح. لا يتم افتراض وجود رصيد فعلي في Saving؛ إذا لم يتوفر الرصيد فلا تضع علامة التنفيذ قبل التحويل.

إذا كان البند السالب نفسه حساب استقبال الإجمالي، أو لم يحدَّد حساب استقبال سليم داخل البنك، لا يعرض التطبيق توجيهًا تخمينيًا. هذا التغيير في العرض فقط، دون أي تعديل لبياناتك.

## الجديد في V8: تسويات الشهر الحالي

بمجرد فتح شهر نوفمبر تستطيع تسجيل تسويات نوفمبر قبل نزول الراتب. تنعكس فورًا على مبالغ البنود والإجمالي والمتبقي. **لا ترحّل التسويات تلقائيًا إلى ديسمبر**. تحفظ كل عملية على البندين داخل سجل نوفمبر، ويمكن تعديلها أو حذفها قبل التأكيد.

لو كانت هناك تسويات معلّقة محفوظة من نسخة V7، يحوّلها V8 مرة واحدة إلى **أحدث شهر موجود** ثم يفرغ قائمة التسويات القديمة. صدّر نسخة جديدة بعد التحديث.

## إدخال بياناتك الشخصية

**مهم:** هذه الحزمة خالية من مبالغك وأسماء الأشخاص الخاصة بك حتى لا تُنشر في مستودع قد يكون عامًا.

- إذا لديك بيانات سابقة في الموقع نفسه ومن نفس المتصفح، التطبيق يحاول قراءتها تلقائيًا.
- إذا لديك نسخة احتياطية من إصدار قديم، افتح `⋯ → استعادة نسخة` واخترها.
- إذا تبدأ من الصفر، استعد **نسختك الخاصة الأحدث** من ملف JSON. ملف نوفمبر الذي زوّدتني به محفوظ منفصلًا عن ZIP؛ لا تضعه داخل مستودع GitHub.
- **لا ترفع ملف البيانات الخاصة أو النسخ الاحتياطية JSON إلى GitHub مطلقًا.**

## النسخ الاحتياطي

من قائمة `⋯` اضغط **نسخة احتياطية**. في Safari على الآيفون ستظهر ورقة المشاركة إذا كان المتصفح يدعم مشاركة الملفات؛ اختر **حفظ في الملفات**. في المتصفحات الأخرى يُطلب تنزيل ملف JSON. يوجد أيضًا خيار **نسخ النسخة نصيًا** إذا منع المتصفح الحفظ، ويمكنك حفظ النص في ملف `.json`.

للاستعادة استخدم `⋯ → استعادة نسخة` واختر ملف JSON. قبل الاستبدال سيطلب التطبيق موافقتك. يُفضل عمل نسخة احتياطية بعد أي تعديل كبير وقبل تغيير الجهاز أو الرابط أو حذف بيانات المتصفح.

## ملاحظات

- لا يحتاج الموقع خادمًا أو API أو حسابًا بنكيًا متصلًا.
- البيانات في `localStorage` في المتصفح، لذلك قد تضيع إذا حذفت بيانات الموقع؛ النسخة الاحتياطية مهمة.
- علامات تيك الراجحي وSTC وبرق مرتبطة افتراضيًا بـ`Investment` و`رصيد` و`هوم`، ولا تُحسب مبالغ التحويل الإجمالي مرتين. `رصيد` و`هوم` يبدأان بصفر لتجنب تكرار المبالغ ويمكن تعديلهما من التطبيق.
- شريط الإنجاز يحسب قيمة البنود التي تم تأكيدها فقط، وليس تيك البنك مرة إضافية.

## اختبار الاستعادة

ملفات التطبيق عامة ولا تحتوي بيانات المستخدم. نسخة JSON الخاصة محفوظة منفصلة. الاستعادة من `⋯ → استعادة نسخة` تقبل مخطط V7 وV8، ويظل مفتاح التخزين المحلي كما هو لاستمرارية بيانات الموقع السابق.
